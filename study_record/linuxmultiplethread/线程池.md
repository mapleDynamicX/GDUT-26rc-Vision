# 线程池

我们来详细介绍一下 C++ 中的线程池。

### 1. 什么是线程池？

**线程池（Thread Pool）** 是一种并发编程的设计模式，它预先创建一组固定数量的工作线程，这些线程会持续等待并执行提交给线程池的任务。线程池通过复用已创建的线程，避免了频繁创建和销毁线程的开销，从而提高了系统的性能和资源利用率。

### 2. 线程池的核心组件

一个典型的线程池通常包含以下几个核心组件：

- **线程池管理器（ThreadPool Manager）**：负责创建、管理和销毁线程池，以及向线程池提交任务。
- **工作线程（Worker Threads）**：线程池中预先创建的线程，它们会不断从任务队列中获取任务并执行。
- **任务队列（Task Queue）**：用于存储等待执行的任务。当任务提交到线程池时，会先被放入任务队列中，等待工作线程来处理。
- **任务接口（Task Interface）**：定义了任务的执行逻辑，通常是一个抽象类或函数对象。

### 3. 线程池的工作流程

线程池的工作流程通常如下：

1. **初始化线程池**：创建指定数量的工作线程，并让它们进入等待状态。
2. **提交任务**：当有新任务需要执行时，通过线程池提供的接口将任务添加到任务队列中。
3. **唤醒工作线程**：当任务队列中有新任务时，会唤醒一个或多个等待中的工作线程。
4. **执行任务**：被唤醒的工作线程从任务队列中取出任务，并执行任务的逻辑。
5. **任务完成**：任务执行完成后，工作线程不会退出，而是继续等待下一个任务。
6. **关闭线程池**：当不再需要线程池时，关闭线程池，此时会停止接受新任务，并等待所有已提交的任务执行完成，最后销毁所有工作线程。

### 4. C++ 中实现线程池的关键技术

在 C++ 中实现线程池，通常需要使用以下技术：

- **`std::thread`**：用于创建工作线程。
- **`std::mutex`** 和 **`std::condition_variable`**：用于实现线程间的同步和通信。
  - `std::mutex` 用于保护任务队列的访问，避免多个线程同时修改任务队列。
  - `std::condition_variable` 用于在任务队列中有新任务时唤醒等待的工作线程，以及在任务队列为空时让工作线程进入等待状态。
- **`std::queue`**：用于实现任务队列，存储等待执行的任务。
- **`std::function`**：用于存储任务，可以将各种可调用对象（函数指针、lambda 表达式、函数对象等）封装成一个任务。

### 5. 简单的 C++ 线程池实现示例

下面是一个简单的 C++ 线程池实现示例，使用了 C++11 及以上版本的特性：

```cpp
#include <iostream>
#include <vector>
#include <queue>
#include <thread>
#include <mutex>
#include <condition_variable>
#include <functional>
#include <future>

class ThreadPool {
public:
    // 构造函数，创建指定数量的工作线程
    explicit ThreadPool(size_t threadCount) : stop(false) {
        for (size_t i = 0; i < threadCount; ++i) {
            workers.emplace_back([this] {
                while (true) {
                    std::function<void()> task;
                    {
                        // 锁定互斥量
                        std::unique_lock<std::mutex> lock(this->mutex);
                        // 等待任务队列中有任务或线程池停止
                        this->condition.wait(lock, [this] {
                            return this->stop || !this->tasks.empty();
                        });
                        // 如果线程池停止且任务队列为空，则退出线程
                        if (this->stop && this->tasks.empty()) {
                            return;
                        }
                        // 从任务队列中取出一个任务
                        task = std::move(this->tasks.front());
                        this->tasks.pop();
                    }
                    // 执行任务
                    task();
                }
            });
        }
    }

    // 析构函数，关闭线程池
    ~ThreadPool() {
        {
            std::unique_lock<std::mutex> lock(mutex);
            stop = true;
        }
        // 唤醒所有等待的工作线程
        condition.notify_all();
        // 等待所有工作线程执行完成
        for (std::thread& worker : workers) {
            worker.join();
        }
    }

    // 提交任务到线程池
    template <typename F, typename... Args>
    auto enqueue(F&& f, Args&&... args) -> std::future<typename std::result_of<F(Args...)>::type> {
        // 推断任务的返回类型
        using return_type = typename std::result_of<F(Args...)>::type;

        // 创建一个 packaged_task，用于包装任务
        auto task = std::make_shared<std::packaged_task<return_type()>>(
            std::bind(std::forward<F>(f), std::forward<Args>(args)...)
        );

        // 获取任务的 future 对象，用于获取任务执行结果
        std::future<return_type> res = task->get_future();
        {
            std::unique_lock<std::mutex> lock(mutex);

            // 如果线程池已经停止，则不接受新任务
            if (stop) {
                throw std::runtime_error("enqueue on stopped ThreadPool");
            }

            // 将任务添加到任务队列中
            tasks.emplace([task]() { (*task)(); });
        }
        // 唤醒一个等待的工作线程
        condition.notify_one();
        return res;
    }

private:
    // 工作线程列表
    std::vector<std::thread> workers;
    // 任务队列
    std::queue<std::function<void()>> tasks;
    // 互斥量，用于保护任务队列的访问
    std::mutex mutex;
    // 条件变量，用于线程间的同步
    std::condition_variable condition;
    // 线程池停止标志
    bool stop;
};

// 示例：使用线程池执行任务
void taskFunction(int id, const std::string& message) {
    std::cout << "Task " << id << " executing: " << message << std::endl;
    // 模拟任务执行耗时
    std::this_thread::sleep_for(std::chrono::seconds(1));
    std::cout << "Task " << id << " completed" << std::endl;
}

int main() {
    // 创建一个包含 3 个工作线程的线程池
    ThreadPool pool(3);

    // 提交 5 个任务到线程池
    for (int i = 0; i < 5; ++i) {
        pool.enqueue(taskFunction, i, "Hello, ThreadPool!");
    }

    // 等待所有任务执行完成（这里简单地等待 2 秒，实际应用中应该使用 future 来等待）
    std::this_thread::sleep_for(std::chrono::seconds(2));

    return 0;
}
```

### 6. 线程池的优势

使用线程池具有以下几个明显的优势：

- **提高性能**：避免了频繁创建和销毁线程的开销，因为线程是预先创建并复用的。
- **资源控制**：可以限制线程池中的线程数量，避免因创建过多线程而导致系统资源耗尽。
- **提高响应速度**：当有新任务提交时，不需要等待线程创建，可以立即由空闲的工作线程执行。
- **简化并发编程**：线程池隐藏了线程管理的细节，开发者只需要关注任务的实现和提交，不需要关心线程的创建、同步和销毁。

### 7. 线程池的应用场景

线程池适用于以下场景：

- **服务器端编程**：如 Web 服务器、数据库服务器等，需要处理大量的并发请求。
- **批量处理任务**：如数据处理、图像处理、文件转换等，可以将大量的任务提交到线程池，由多个线程并行处理。
- **异步任务执行**：如在 GUI 应用中，将耗时的操作（如网络请求、文件读写）提交到线程池，避免阻塞主线程，提高应用的响应性。

### 总结

线程池是 C++ 中实现并发编程的一种重要方式，它通过预先创建和复用线程，提高了系统的性能和资源利用率。在实际应用中，我们可以根据具体需求选择合适的线程池实现，或者使用第三方库（如 Boost.ThreadPool、Intel TBB 等）提供的线程池功能。

我们来详细解释一下 `std::function<void()>` 这个语法，并结合线程池的例子说明如何使用它。

### 1. `std::function<void()>` 是什么？

`std::function<void()>` 是 C++11 引入的一种通用、多态的函数封装器。它的核心作用是**可以存储和调用任何可调用对象（callable object）**，只要该对象的**调用签名**与 `std::function` 的模板参数匹配。

我们来拆解一下这个语法：

- **`std::function`**: 这是一个模板类，定义在 `<functional>` 头文件中。它就像一个 “函数容器”。
- **`<void()>`**: 这是 `std::function` 的模板参数，它定义了**函数签名（Function Signature）**。
  - `void`: 表示这个函数没有返回值。
  - `()`: 表示这个函数不接受任何参数。

所以，`std::function<void()>` 可以理解为：**一个可以存储 “不接受任何参数且没有返回值” 的函数或函数对象的容器**。

### 2. 为什么线程池需要 `std::function<void()>`？

线程池的任务队列 `std::queue<std::function<void()>> tasks` 需要存储各种类型的任务。这些任务可能是：

- 一个普通的全局函数。
- 一个类的成员函数。
- 一个 lambda 表达式。
- 一个函数对象（仿函数）。

这些任务的类型各不相同，它们的类型是 `void (*)()`、`void (MyClass::*)()`、`lambda` 等，如果没有 `std::function<void()>`，你无法将它们存储在同一个 `std::queue` 中。

`std::function<void()>` 就提供了一个统一的类型接口，它能容纳所有这些不同类型但调用方式相同（无参、无返回值）的可调用对象。这使得线程池的任务队列的设计变得非常简洁和灵活。

### 3. 如何使用 `std::function<void()>`？

你可以用以下几种常见的方式来创建和使用 `std::function<void()>` 对象。

#### 示例 1：存储普通函数

```cpp
#include <iostream>
#include <functional>

void print_hello() {
    std::cout << "Hello, World!" << std::endl;
}

int main() {
    // 将普通函数赋值给 std::function<void()>
    std::function<void()> func = print_hello;

    // 像调用普通函数一样调用它
    func(); // 输出: Hello, World!

    return 0;
}
```

- `push_back` 会先创建一个临时的 `Person` 对象，然后再将其移动（或拷贝）到 `vector` 中。
- `emplace_back` 则直接在 `vector` 的末尾构造 `Person` 对象，不需要创建临时对象。

## 3. 关键区别总结

| 特性         | `push_back`              | `emplace_back`      |
| ---------- | ------------------------ | ------------------- |
| **对象创建方式** | 先创建临时对象，再复制 / 移动到容器中     | 直接在容器中构造对象，无临时对象    |
| **构造函数调用** | 可能调用拷贝构造函数或移动构造函数        | 直接调用元素的构造函数（完美转发参数） |
| **性能**     | 有额外的拷贝 / 移动开销            | 开销更小，性能更高           |
| **适用场景**   | 当你已经有一个现成的对象，想要将其添加到容器中时 | 当你想要创建一个新对象并添加到容器中时 |
| **C++ 版本** | C++98 及以后                | C++11 及以后           |

| 特性       | 左值引用 (`T&`)     | 右值引用 (`T&&`) |
| -------- | --------------- | ------------ |
| **绑定对象** | 只能绑定左值          | 只能绑定右值       |
| **可修改性** | 可以修改（非 `const`） | 可以修改         |
| **主要用途** | 传递参数、返回左值       | 移动语义、完美转发    |
| **生命周期** | 与绑定对象一致         | 与绑定的右值一致     |

## 2. 左值引用（Lvalue Reference）

### 定义

- 用 `T&` 表示，只能绑定到**左值**。

### 特点

- 可以修改绑定的对象（除非是 `const` 左值引用）。
- 生命周期与绑定的对象一致。

### 例子

```cpp
int x = 10;
int& ref = x; // 左值引用绑定到左值 x
ref = 20; // 修改 ref 会影响 x
```

### `const` 左值引用

- 用 `const T&` 表示，可以绑定到**左值或右值**。
- 不能修改绑定的对象。

```cpp
const int& ref1 = x; // 绑定左值
const int& ref2 = 10; // 绑定右值
```

## 3. 右值引用（Rvalue Reference）

### 定义

- 用 `T&&` 表示，只能绑定到**右值**。

### 特点

- 通常用于 “窃取” 右值的资源（移动语义）。
- 生命周期与绑定的右值一致（通常是临时对象）。

### 例子

```cpp
int&& ref = 10; // 右值引用绑定到右值 10
ref = 20; // 可以修改

std::string&& s = std::string("hello"); // 绑定临时对象
```

## 5. 右值引用的核心作用

### 移动语义（Move Semantics）

- 通过右值引用，我们可以 “窃取” 临时对象的资源，避免拷贝。
- 例子：

```cpp
class MyString {
public:
    char* data;
    MyString(const char* s) {
        data = new char[strlen(s) + 1];
        strcpy(data, s);
    }

    // 移动构造函数
    MyString(MyString&& other) noexcept {
        data = other.data; // 窃取资源
        other.data = nullptr; // 避免悬空指针
    }

    ~MyString() {
        delete[] data;
    }
};

MyString func() {
    return MyString("hello"); // 返回临时对象（右值）
}

MyString s = func(); // 调用移动构造函数，避免拷贝
```

### 完美转发（Perfect Forwarding）

- 在模板中，右值引用可以保持参数的左值 / 右值属性。
- 例子

```cpp
template <typename T>
void forward(T&& arg) {
    process(std::forward<T>(arg)); // 保持 arg 的属性
}

forward(10); // arg 是右值
int x = 20;
forward(x); // arg 是左值
```

## 6. 总结

- **左值引用**：用于传递左值，避免拷贝，可修改对象。
- **右值引用**：用于绑定右值，实现移动语义和完美转发，提升性能。
- 右值引用是 C++11 引入的重要特性，主要解决临时对象的拷贝开销问题。

`std::bind` 是 C++11 标准库中的一个强大工具，定义在 `<functional>` 头文件中。它用于**将一个可调用对象（如函数、Lambda 表达式、成员函数等）与其部分或全部参数 “绑定” 在一起，生成一个新的可调用对象**。这个新的可调用对象在被调用时，会将绑定的参数传递给原始的可调用对象。

---

### 1. 核心功能

`std::bind` 的核心作用是**参数绑定和函数适配**：

- **固定参数**：将函数的部分或全部参数预先绑定为特定的值，生成一个参数更少的新函数。
- **调整参数顺序**：通过占位符（`std::placeholders::_1, _2, ...`）重新排列原始函数的参数顺序。
- **适配函数签名**：将一个多参数函数适配为一个少参数或参数类型不同的函数，以满足特定的调用需求（如回调函数）。

```cpp
#include <functional>

// 绑定普通函数/ Lambda / 仿函数
auto bound_func = std::bind(original_func, arg1, arg2, ...);

// 绑定成员函数
auto bound_mem_func = std::bind(&ClassName::member_func, instance_ptr, arg1, arg2, ...);
```

- `original_func`：原始的可调用对象（函数指针、Lambda、仿函数等）。
- `arg1, arg2, ...`：绑定的参数，可以是：
  - **具体的值**（如 `10`, `"hello"`）。
  - **占位符**（`std::placeholders::_1`, `_2`, ...），表示新函数被调用时传入的参数。
- `bound_func`：生成的新可调用对象，类型为 `std::function` 或其他可调用类型。

### 3. 关键概念：占位符

`std::bind` 使用占位符来表示**新函数被调用时需要接收的参数**。占位符的命名规则是 `std::placeholders::_n`，其中 `n` 是一个正整数，表示新函数的第 `n` 个参数。

例如：

- `std::placeholders::_1` → 新函数的第一个参数。
- `std::placeholders::_2` → 新函数的第二个参数。
- 以此类推。

占位符的作用是**将新函数的参数 “转发” 给原始函数**。

### 4. 使用示例

#### 示例 1：绑定普通函数（固定参数）

```cpp
#include <iostream>
#include <functional>

int add(int a, int b) {
    return a + b;
}

int main() {
    // 绑定 add 函数的第一个参数为 10，生成一个新函数，只需要传入第二个参数
    auto add10 = std::bind(add, 10, std::placeholders::_1);

    // 调用新函数，传入的参数会作为 add 的第二个参数
    std::cout << add10(5) << std::endl;  // 输出：15（10 + 5）
    std::cout << add10(20) << std::endl; // 输出：30（10 + 20）

    return 0;
}
```

#### 示例 2：调整参数顺序

```cpp
#include <iostream>
#include <functional>

int sub(int a, int b) {
    return a - b;
}

int main() {
    // 绑定 sub 函数，并交换参数顺序（_1 是新函数的第一个参数，_2 是第二个）
    auto reverse_sub = std::bind(sub, std::placeholders::_2, std::placeholders::_1);

    // 调用 reverse_sub(x, y) 等价于 sub(y, x)
    std::cout << reverse_sub(5, 10) << std::endl;  // 输出：5（10 - 5）
    std::cout << reverse_sub(20, 15) << std::endl; // 输出：-5（15 - 20）

    return 0;
}
```

#### 示例 3：绑定成员函数

```cpp
#include <iostream>
#include <functional>
#include <string>

class Person {
public:
    void greet(const std::string& name) {
        std::cout << "Hello, " << name << "! My name is " << m_name << std::endl;
    }

private:
    std::string m_name;
};

int main() {
    Person alice;
    alice.m_name = "Alice";

    // 绑定 Person::greet 成员函数，第一个参数是对象指针（&alice）
    auto greet_alice = std::bind(&Person::greet, &alice, std::placeholders::_1);

    // 调用新函数，传入的参数会作为 greet 的 name 参数
    greet_alice("Bob");   // 输出：Hello, Bob! My name is Alice
    greet_alice("Charlie");// 输出：Hello, Charlie! My name is Alice

    return 0;
}
```

#### 示例 4：绑定 Lambda 表达式

```cpp
#include <iostream>
#include <functional>

int main() {
    auto multiply = [](int a, int b) {
        return a * b;
    };

    // 绑定 Lambda 的第一个参数为 5
    auto multiply_by_5 = std::bind(multiply, 5, std::placeholders::_1);

    std::cout << multiply_by_5(3) << std::endl;  // 输出：15（5 * 3）
    std::cout << multiply_by_5(7) << std::endl;  // 输出：35（5 * 7）

    return 0;
}
```

### 5. 与 `std::function` 结合使用

`std::bind` 生成的可调用对象可以赋值给 `std::function`，这在回调函数、任务队列等场景中非常有用。

```cpp
#include <iostream>
#include <functional>
#include <queue>

void task(int x, const std::string& s) {
    std::cout << "Task: x = " << x << ", s = " << s << std::endl;
}

int main() {
    std::queue<std::function<void()>> task_queue;

    // 绑定 task 函数的参数，并添加到任务队列
    task_queue.push(std::bind(task, 10, "hello"));
    task_queue.push(std::bind(task, 20, "world"));

    // 执行任务
    while (!task_queue.empty()) {
        auto t = task_queue.front();
        t();  // 调用绑定后的函数
        task_queue.pop();
    }

    return 0;
}
```

### 二、`std::forward` 的语法与核心逻辑

#### 1. 语法

```cpp
#include <utility>

template<typename T>
T&& forward(typename std::remove_reference_t<T>& t) noexcept;

template<typename T>
T&& forward(typename std::remove_reference_t<T>&& t) noexcept;
```

- 模板参数 `T`：用于指定转发的目标类型（通常是模板推导的类型）；
- 参数 `t`：待转发的参数（通常是 “万能引用”`T&&` 接收的参数）；
- 返回值：`T&&`（根据 `T` 的类型，折叠为左值引用或右值引用）。

#### 2. 核心逻辑：“条件转发”

`std::forward` 的转发行为**完全依赖模板参数 `T` 的推导结果**，规则如下：

- 若 `T` 是**左值引用类型**（如 `int&`），则 `T&&` 折叠为**左值引用**（`int&`），`forward` 返回左值引用，参数以左值形式转发；
- 若 `T` 是**非引用类型**（如 `int`），则 `T&&` 是**右值引用**（`int&&`），`forward` 返回右值引用，参数以右值形式转发；
- 若 `T` 是 **`const` 左值引用类型 **（如 `const int&`），则 `T&&` 折叠为 `const int&`，`forward` 返回 `const` 左值引用，保留 `const` 修饰。

简单来说：`std::forward<T>(t)` 的作用是 “**如果 `T` 是右值引用类型，就把 `t` 转为右值；否则转为左值**”。

### 三、`std::forward` 的使用条件：必须配合 “万能引用”

`std::forward` 本身无法单独实现完美转发，必须与**万能引用（Universal Reference）** 结合使用。

#### 1. 万能引用的定义

万能引用是指模板参数为 `T&&` 的引用（仅当 `T` 是模板推导的类型时），例如：

```cpp
template<typename T>
void func(T&& t) { // T&& 是万能引用
    // ...
}
```

万能引用的特性是：

- 若传入**左值**（如 `int x; func(x)`），`T` 推导为 `int&`，`T&&` 折叠为 `int&`（左值引用）；
- 若传入**右值**（如 `func(10)`），`T` 推导为 `int`，`T&&` 是 `int&&`（右值引用）；
- 若传入 **`const` 左值 **（如 `const int x; func(x)`），`T` 推导为 `const int&`，`T&&` 折叠为 `const int&`（`const` 左值引用）。

#### 2. 万能引用 + `std::forward`：完美转发组合

只有当 `std::forward` 的模板参数 `T` 是万能引用推导的类型时，才能正确判断参数的原始类型，实现完美转发。

示例：

```cpp
template<typename F, typename... Args>
void perfect_wrapper(F f, Args&&... args) { // Args&& 是万能引用
    f(std::forward<Args>(args)...); // 用 std::forward 转发参数
}
```

- `Args` 是模板推导的类型，`Args&&` 接收参数时会根据原始类型折叠为左值引用 / 右值引用 /`const` 左值引用；
- `std::forward<Args>(args)` 会根据 `Args` 的类型，将 `args` 转为原始的值类别，实现完美转发。

这两个表达式有**本质区别**，核心差异在于 **C++ 可变参数模板展开规则** 与 **括号对表达式解析的影响**—— 前者会导致参数传递错误（仅保留最后一个参数），后者才是正确的完美转发

### 核心结论

| 表达式                                                         | 展开行为                                  | 正确性 |
| ----------------------------------------------------------- | ------------------------------------- | --- |
| `std::bind(std::forward<F>(f), std::forward<F>((args)...))` | 错误：`(args)...` 展开为**逗号表达式**，仅传递最后一个参数 | 错误  |
| `std::bind(std::forward<F>(f), std::forward<F>(args)...)`   | 正确：`args...` 展开为**独立参数**，每个参数都被完美转发   | 正确  |

### 关键概念铺垫

在分析前，先明确两个基础规则：

1. **可变参数模板展开**：`args...` 会将参数包 `args` 中的每个元素（如 `arg1, arg2, arg3`）展开为独立表达式，用逗号分隔；
2. **逗号表达式**：C++ 中 `(a, b, c)` 是逗号表达式，结果为**最后一个子表达式的值**（即 `c`），前序子表达式仅执行但结果被丢弃；
3. **`std::forward` 的作用**：基于参数的原始值类别（左值 / 右值），将参数 “完美转发” 给目标函数，需保证每个参数独立传递。

### 逐行分析

假设场景：`args` 是参数包，包含 3 个元素 `arg1`（int 左值）、`arg2`（double 右值）、`arg3`（string 左值），即 `args = arg1, arg2, arg3`。

#### 1. 错误表达式：`std::forward<F>((args)...)`

展开过程：

- 第一步：`(args)...` 展开为 `(arg1, arg2, arg3)`（括号包裹的逗号表达式）；
- 第二步：`std::forward<F>((arg1, arg2, arg3))` 等价于 `std::forward<F>(arg3)`（逗号表达式仅保留最后一个元素）；

最终 `std::bind` 接收的参数是：`forward(f), forward(arg3)`——**仅传递了最后一个参数**，前两个参数被丢弃，完全不符合预期。

#### 2. 正确表达式：`std::forward<F>(args)...`

展开过程：

- 第一步：`args...` 展开为 `arg1, arg2, arg3`（3 个独立表达式）；
- 第二步：`std::forward<F>(args)...` 展开为 `std::forward<F>(arg1), std::forward<F>(arg2), std::forward<F>(arg3)`（3 个独立的完美转发）；

最终 `std::bind` 接收的参数是：`forward(f), forward(arg1), forward(arg2), forward(arg3)`——**所有参数都被正确转发**，符合 `std::bind` 的参数传递逻辑。

### 额外注意：`std::forward<F>` 的模板参数问题

你的代码中 `std::forward` 的模板参数是 `F`（函数对象的类型），但**正确写法应使用参数包的元素类型**（即 `std::forward<Args>(args)...`，其中 `Args` 是参数包的类型）。

原因：`F` 是函数对象的类型（如 `void(int, double, std::string)`），而 `args` 的元素类型是 `int`、`double` 等，两者不一致会导致 `std::forward` 转发类型错误。

修正后的正确写法：

```cpp
template <typename F, typename... Args>
auto bind_func(F&& f, Args&&... args) {
    return std::bind(std::forward<F>(f), std::forward<Args>(args)...);
}
```

- 括号 `(args)...` 会强制将参数包展开为**逗号表达式**，仅保留最后一个参数，导致错误；
- 无括号 `args...` 会将参数包展开为**独立表达式**，配合 `std::forward<Args>(args)...` 实现所有参数的完美转发，是正确写法；
- 实际开发中，`std::bind` 结合完美转发时，必须使用 `std::forward<Args>(args)...` 的形式。

```cpp
class ThreadPool
{
public:
    explicit ThreadPool(size_t ThreadNum)
    :_stop(false)
    {
        for (size_t i = 0; i < ThreadNum; i++)
        {
            _threads.emplace_back([this] {
                while (true)
                {
                    std::function<void()> task;
                    {
                        std::unique_lock<std::mutex> lock(_mtx);
                        _condition.wait(lock, [this] {return !_tasks.empty() || _stop; });
                        if (_stop && _tasks.empty())
                        {
                            return;
                        }
                        task = std::move(_tasks.front());
                        _tasks.pop();
                    }
                    task();
                }

                });
        }
    }

    ~ThreadPool()
    {
        {
            std::unique_lock<std::mutex> lock(_mtx);
            _stop = true;
        }
        _condition.notify_all();
        for (auto& t : _threads)
        {
            t.join();
        }
    }

    template<typename F, typename... Args>
    void enqueue(F&& f, Args&&... args)
    {
        std::function<void()> task = std::bind(std::forward<F>(f), std::forward<Args>(args)...);
        {
            std::unique_lock<std::mutex> lock(_mtx);
            _tasks.emplace(std::move(task));
        }
        _condition.notify_one();
    }

private:
    std::vector<std::thread> _threads;
    std::queue<std::function<void()>> _tasks;

    std::mutex _mtx;
    std::condition_variable _condition;

    bool _stop;
};
```
