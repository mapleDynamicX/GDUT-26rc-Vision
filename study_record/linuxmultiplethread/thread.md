## 一、本质定义：进程 vs 线程

### 1. 进程（Process）

- **官方定义**：操作系统进行**资源分配和调度的基本单位**（资源包括 CPU、内存、文件句柄、网络端口等）。
- **通俗理解**：一个独立运行的程序实例（如 ROS 节点`rosrun pcl_ros pointcloud_to_laserscan`、OpenPCDet 的推理程序），拥有自己的 "独立王国"（独立地址空间、资源集合）。
- **内核视角**：进程是内核中的一个`task_struct`结构体（Linux 内核），包含进程 ID（PID）、内存映射表、文件描述符表、寄存器上下文、优先级等信息。

### 2. 线程（Thread）

- **官方定义**：操作系统进行**CPU 调度和执行的基本单位**（线程本身不分配资源，仅共享所属进程的资源）。
- **通俗理解**：进程内的 "执行单元"（如 ROS 节点中处理点云回调的线程、PCL 多线程点云滤波的子线程），多个线程在同一 "王国" 内协同工作，共享 "王国资源"（内存、文件句柄等）。
- **内核视角**：线程是内核中的`task_struct`结构体（Linux 中线程本质是 "轻量级进程"），但与同进程的其他线程共享**地址空间、文件描述符表、信号处理方式**，仅拥有独立的**程序计数器（PC）、寄存器集合、栈空间**。

| **内存地址空间**    | 独立（虚拟地址空间不重叠，进程 A 无法直接访问进程 B 的内存）                | 共享（同一进程的所有线程访问同一虚拟地址空间，可直接读写全局变量）         | 1. 进程间共享点云需用共享内存（如`boost::interprocess`）；2. 线程间直接访问`pcl::PointCloud`对象 |

| **适用场景**      | 独立功能模块、需要资源隔离、容错性要求高的场景                          | 并行计算、高频任务、数据共享密集的场景                       | 1. 进程：ROS 节点（感知、规划、控制）、独立工具（数据录制、可视化）；2. 线程：点云滤波、特征提取、多传感器数据同步         |

## 三、底层原理：为什么有这些差异？

### 1. 内存空间差异（核心原因）

#### 进程的内存空间（独立）：

每个进程拥有**4GB 虚拟地址空间**（32 位系统），分为：

- 代码段（.text）：存放程序指令；
- 数据段（.data/.bss）：存放全局变量、静态变量；
- 堆（heap）：动态内存分配（如`new`/`malloc`）；
- 栈（stack）：函数调用、局部变量；
- 内核空间（高地址）：内核数据结构和系统调用。

进程间的内存空间完全隔离，进程 A 无法直接访问进程 B 的堆 / 栈内存（需通过 IPC 机制间接访问），因此安全性高，但数据共享成本高。

#### 线程的内存空间（共享）：

同一进程的所有线程共享**代码段、数据段、堆、文件句柄**，仅栈空间独立（每个线程有自己的栈，默认大小为 8MB）。例如：

- 线程 A 创建的`pcl::PointCloud<pcl::PointXYZRGB>::Ptr cloud`（堆内存），线程 B 可直接访问；
- 线程 A 的局部变量`int count`（栈内存），线程 B 无法直接访问。

内存共享导致线程切换无需刷新地址空间，切换开销小，但必须通过同步机制避免 "竞态条件"（如两个线程同时修改同一云点的坐标）。

### 2. 调度机制差异（Linux 内核视角）

- **进程调度**：内核按进程的优先级、CPU 时间片分配 CPU 资源，调度时需切换**页表（地址空间映射）、文件描述符表、信号处理上下文**，开销大。
- **线程调度**：Linux 中线程被称为 "轻量级进程（LWP）"，与进程共用同一`task_struct`中的大部分字段，调度时仅需切换**程序计数器（PC）、寄存器、栈指针**，无需修改地址空间相关信息，开销仅为进程的 1/10~1/100。

### 3. 通信机制的底层实现

- **进程间通信（IPC）**：
  - ROS 话题 / 服务：基于 TCP/UDP Socket 实现（跨进程、跨主机）；
  - 共享内存：内核分配一块物理内存，多个进程通过映射到自身虚拟地址空间访问（高效，适合点云等大数据传输）；
  - 消息队列：内核维护的消息链表，进程通过系统调用发送 / 接收消息（异步通信）。
- **线程间通信**：
  - 全局变量：直接读写（需同步）；
  - 条件变量（`std::condition_variable`）：线程间同步通知（如点云处理完成后通知可视化线程）；
  - 原子变量（`std::atomic`）：无锁同步（适合计数器、标志位）。

### 1. 成员函数指针的特殊性

在 C++ 中，一个类的非静态成员函数和一个普通的全局函数有一个关键的区别：**非静态成员函数必须通过一个对象来调用**。它隐含地需要一个指向类实例的指针（即 `this` 指针）作为其第一个参数。

因此，一个成员函数的 “地址” 不仅仅是一个代码地址，它还与它所属的类紧密相关。我们不能像对待普通函数那样，直接用函数名来获取它的地址。

### 2. 语法规则：`&` 是必须的

C++ 标准规定，要获取一个非静态成员函数的指针，必须使用**取地址运算符 `&`**，并加上**类名限定 `A::`**。

- **正确写法**: `&A::func`
- **错误写法**: `A::func` (在需要指针的上下文中)

`A::func` 这个表达式本身**不代表一个指针**。它只能在以下两种特定上下文中使用：

a) **作为函数调用的一部分**：当你有一个对象 `a` 时，`a.A::func()` 是一个合法的函数调用（虽然通常我们直接写 `a.func()`）。这里的 `A::func` 是在指定要调用的成员函数。

b) **在 `decltype` 等类型推导中**：`decltype(A::func)` 可以推导出成员函数的类型。

但在需要一个**指针值**的地方（例如，赋值给一个指针变量，或者作为 `std::thread` 的参数），`A::func` 是不合法的，必须写成 `&A::func`。

### 3. 编译器的解析

当编译器看到 `A::func` 时，它并不知道你是想调用这个函数，还是想获取它的地址。在需要指针的上下文中，你必须用 `&` 来明确告诉编译器：“我想要的是这个函数的地址，而不是调用它”。

- `A::func()`: 调用成员函数 `func`。
- `&A::func`: 获取成员函数 `func` 的指针。

## 1. 什么是 `std::shared_ptr`？

`std::shared_ptr` 是 C++11 引入的一种**智能指针**，它允许多个指针共享同一个动态分配的对象。它的核心特点是通过**引用计数**（Reference Counting）来管理对象的生命周期：

- 当一个 `std::shared_ptr` 指向某个对象时，引用计数加 1。
- 当 `std::shared_ptr` 被销毁（如超出作用域）或重新赋值时，引用计数减 1。
- 当引用计数变为 0 时，它指向的对象会被自动释放（调用 `delete`），从而避免内存泄漏。

`std::shared_ptr` 定义在 `<memory>` 头文件中。

## 2. 基本用法

### 2.1 创建 `std::shared_ptr`

有两种常用方式创建 `std::shared_ptr`：

**方式 1：使用 `std::make_shared`（推荐）**

```cpp
std::shared_ptr<MyClass> ptr1 = std::make_shared<MyClass>(10);
```

**方式 2：使用原始指针构造**

```cpp
std::shared_ptr<MyClass> ptr2(new MyClass(20));
```

⚠️ **注意**：尽量使用 `std::make_shared`，因为它更安全（避免内存泄漏）且性能更好。

### 2.2 共享所有权

多个 `std::shared_ptr` 可以指向同一个对象，它们会共享引用计数：

```cpp
int main() {
    std::shared_ptr<MyClass> ptr1 = std::make_shared<MyClass>(10);
    std::cout << "ptr1 use count: " << ptr1.use_count() << std::endl; // 输出: 1

    // 拷贝构造，引用计数变为 2
    std::shared_ptr<MyClass> ptr2 = ptr1;
    std::cout << "ptr1 use count: " << ptr1.use_count() << std::endl; // 输出: 2
    std::cout << "ptr2 use count: " << ptr2.use_count() << std::endl; // 输出: 2

    // 赋值操作，ptr3 也指向同一个对象，计数变为 3
    std::shared_ptr<MyClass> ptr3;
    ptr3 = ptr1;
    std::cout << "ptr1 use count: " << ptr1.use_count() << std::endl; // 输出: 3

    return 0;
}
```

### 2.3 常用操作

| 操作                       | 说明                  |
| ------------------------ | ------------------- |
| `ptr.use_count()`        | 返回当前引用计数            |
| `ptr.reset()`            | 释放当前指针的所有权，引用计数减 1  |
| `ptr.reset(new MyClass)` | 重新指向新对象，原对象引用计数减 1  |
| `ptr.get()`              | 返回原始指针（尽量避免使用）      |
| `ptr.reset(nullptr)`     | 等价于 `ptr.reset()`   |
| `std::swap(ptr1, ptr2)`  | 交换两个 shared_ptr 的内容 |
