# lds

### Lds 类完整解析

`Lds`（Lidar Data Source）是 Livox ROS 驱动中**激光雷达数据源的抽象基类**，定义了所有类型数据源（原始雷达、Hub、LVX 文件）的通用接口和核心数据管理逻辑，是驱动 “数据生产侧” 的核心抽象（子类如 `LdsLidar`、`LdsLvxFile` 会实现具体的数据源读取逻辑）。

以下按 “构造 / 析构→公有成员函数→静态成员→公有变量→保护变量→私有变量” 的维度，逐成员详解：

## 一、类核心定位

- 抽象层：统一不同数据源（硬件 / Hub/LVX 文件）的核心行为（数据存储、退出控制、队列管理等），子类只需实现差异化逻辑（如硬件读取、文件解析）；
- 数据管理：集中管理所有雷达设备的状态、数据队列、同步信号量，是 “生产者” 核心（向队列推送原始数据，供 Lddc 消费）；
- 线程安全：通过信号量、退出标志位保证多线程（生产 / 消费）下的数据安全。

## 二、构造函数 & 析构函数

| 成员声明                                                      | 功能与设计意图                                                                                                                                                                                                                                    |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Lds(const double publish_freq, const uint8_t data_src);` | ① 构造函数：初始化数据源的核心参数；<br><br>② 参数说明：<br><br>- `publish_freq`：数据发布频率（Hz），控制生产数据的速率；<br><br>- `data_src`：数据源类型（对应 `LidarDataSourceType` 枚举，如 `kSourceRawLidar`）；<br><br>③ 核心操作：初始化 `publish_freq_`/`data_src_` 成员变量，创建信号量，初始化雷达设备数组 `lidars_`。 |
| `virtual ~Lds();`                                         | ① 虚析构函数：保证子类析构时先调用子类析构，再调用基类析构，避免内存泄漏；<br><br>② 核心操作：释放雷达设备资源、销毁信号量、清空数据队列。                                                                                                                                                                |

## 三、公有成员函数（按功能分类）

### 1. 数据存储：将原始数据写入雷达设备的队列（生产者核心接口）

| 函数声明                                           | 功能与设计意图                                                                                                                                                                         |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `void StorageImuData(ImuData* imu_data);`      | ① 存储 IMU 数据到对应雷达的 IMU 队列；<br><br>② 参数 `imu_data`：指向原始 IMU 数据的指针（包含角速度、加速度、时间戳等）；<br><br>③ 核心逻辑：根据 IMU 数据关联的雷达 ID，找到对应 `LidarDevice`，将数据推入其 IMU 队列，释放 `imu_semaphore_` 信号量通知消费者。 |
| `void StoragePointData(PointFrame* frame);`    | ① 存储激光雷达原始点云帧数据（硬件 / Hub 数据源专用）；<br><br>② 参数 `frame`：指向原始点云帧的指针（包含多包点数据、帧时间戳、雷达 ID 等）；<br><br>③ 核心逻辑：解析帧数据中的雷达 ID，将点数据拆分后推入对应 `LidarDevice` 的点云队列，释放 `pcd_semaphore_` 信号量。      |
| `void StorageLvxPointData(PointFrame* frame);` | ① 存储 LVX 文件解析出的点云帧数据（LVX 文件数据源专用）；<br><br>② 与 `StoragePointData` 逻辑类似，但适配 LVX 文件的帧格式（如包含文件时间戳、帧索引等）；<br><br>③ 区分设计：避免硬件数据和文件数据的格式处理冲突，提升代码可读性。                                  |

### 2. 句柄 / 数据推送：管理雷达句柄，推送原始数据包

| 函数声明                                                                                          | 功能与设计意图                                                                                                                                                                                                                                                                  |
| --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `int8_t GetHandle(const uint8_t lidar_type, const PointPacket* lidar_point);`                 | ① 获取雷达设备的 “句柄（handle）”（即 `lidars_` 数组的索引）；<br><br>② 参数：<br><br>- `lidar_type`：雷达型号（如 Mid-40、Avia）；<br><br>- `lidar_point`：原始点数据包（包含雷达唯一标识）；<br><br>③ 返回值：<br><br>- 成功：返回雷达句柄（0~kMaxSourceLidar-1）；<br><br>- 失败：返回 -1（如雷达未注册、超出最大数量）；<br><br>④ 核心作用：将物理雷达映射为数组索引，简化多雷达管理。 |
| `void PushLidarData(PointPacket* lidar_data, const uint8_t index, const uint64_t base_time);` | ① 推送单包原始点数据到指定雷达的队列；<br><br>② 参数：<br><br>- `lidar_data`：单包原始点数据；<br><br>- `index`：雷达句柄（数组索引）；<br><br>- `base_time`：时间基准（用于校准点数据的时间戳）；<br><br>③ 核心逻辑：将数据包时间戳校准后，推入 `lidars_[index]` 的点云队列，是 `StoragePointData` 的底层支撑。                                                     |

### 3. 雷达 / 数据源重置：恢复初始状态，适配数据源切换

| 函数声明                                                                 | 功能与设计意图                                                                                                                                                                                                             |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `static void ResetLidar(LidarDevice *lidar, uint8_t data_src);`      | ① 静态函数：重置单个雷达设备的状态；<br><br>② 参数：<br><br>- `lidar`：指向待重置的雷达设备；<br><br>- `data_src`：目标数据源类型；<br><br>③ 核心操作：清空雷达的点云 / IMU 队列、重置连接状态（如从 `kConnectStateSampling` 改为 `kConnectStateInit`）、初始化数据缓存，适配数据源切换（如从硬件切到 LVX 文件）。 |
| `static void SetLidarDataSrc(LidarDevice *lidar, uint8_t data_src);` | ① 静态函数：设置单个雷达设备的数据源类型；<br><br>② 核心作用：标记雷达数据的来源（硬件 / Hub/LVX），让后续数据处理逻辑适配不同来源的格式。                                                                                                                                    |
| `void ResetLds(uint8_t data_src);`                                   | ① 重置整个数据源（所有雷达）；<br><br>② 核心逻辑：遍历 `lidars_` 数组，调用 `ResetLidar` 重置每个雷达，清空全局缓存（`cache_index_`），重置退出标志位 `request_exit_`，用于数据源切换或驱动重启。                                                                                  |

### 4. 退出控制：管理数据源的退出流程（线程优雅退出）

| 函数声明                                                 | 功能与设计意图                                                                                                                    |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `void RequestExit();`                                | ① 触发数据源退出请求；<br><br>② 核心操作：将私有变量 `request_exit_` 设为 `true`，通知所有生产 / 消费线程停止工作；<br><br>③ 调用时机：ROS 节点退出、硬件断开、用户手动停止驱动时。       |
| `void CleanRequestExit() { request_exit_ = false; }` | ① 清空退出请求标志；<br><br>② 内联函数：简化代码，用于驱动重启时恢复数据源状态。                                                                             |
| `bool IsRequestExit() { return request_exit_; }`     | ① 检查是否收到退出请求；<br><br>② 内联函数：消费线程（如 Lddc 的数据分发线程）循环中调用，判断是否终止工作；<br><br>③ 核心作用：保证线程 “优雅退出”，而非暴力终止。                          |
| `virtual void PrepareExit(void);`                    | ① 虚函数：预处理退出逻辑（子类可重写）；<br><br>② 基类逻辑：释放信号量（避免消费线程阻塞）、停止数据生产；<br><br>③ 子类扩展：如 `LdsLidar` 重写后会断开硬件连接，`LdsLvxFile` 重写后会关闭文件句柄。 |

### 5. 队列状态检查：判断数据队列是否为空 / 停止读取

| 函数声明                         | 功能与设计意图                                                                                                         |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `bool IsAllQueueEmpty();`    | ① 检查所有雷达的点云 / IMU 队列是否为空；<br><br>② 返回值：`true` 表示全空，`false` 表示仍有未处理数据；<br><br>③ 调用时机：驱动退出时，等待队列清空后再终止，避免数据丢失。    |
| `bool IsAllQueueReadStop();` | ① 检查所有雷达的队列是否停止读取（如硬件断开导致无新数据）；<br><br>② 核心逻辑：遍历雷达设备，判断连接状态 + 队列是否长期无新数据；<br><br>③ 作用：识别数据源异常（如硬件掉线），触发告警或退出流程。 |

### 6. 频率获取：获取数据发布频率

| 函数声明                                                 | 功能与设计意图                                                           |
| ---------------------------------------------------- | ----------------------------------------------------------------- |
| `double GetLdsFrequency() { return publish_freq_; }` | ① 内联函数：获取数据源的发布频率；<br><br>② 作用：消费线程（Lddc）根据该频率控制数据发布速率，保证与生产速率匹配。 |

## 四、静态成员（全局共享）

| 成员声明                              | 功能与设计意图                                                                                                                               |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `static CacheIndex cache_index_;` | ① 静态缓存索引：全局管理所有雷达的数据包缓存索引；<br><br>② `CacheIndex`：自定义结构体，包含每个雷达的缓存读写指针、缓存大小等；<br><br>③ 静态设计：所有 Lds 实例共享同一套缓存索引，避免多实例缓存冲突，适配多雷达组网的缓存管理。 |

## 五、公有成员变量（数据共享，供外部消费）

| 变量声明                                    | 类型 / 含义                                                                                                             | 设计意图                                                                                                                               |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `uint8_t lidar_count_;`                 | 无符号字符型，当前已连接的雷达数量；<br><br>注释：“Lidar access handle”（雷达访问句柄总数）                                                        | 供外部（如 Lddc）遍历雷达设备时使用（如 `for (i=0; i<lidar_count_; i++)`），是多雷达管理的核心变量。                                                              |
| `LidarDevice lidars_[kMaxSourceLidar];` | `LidarDevice` 数组，索引为雷达句柄；<br><br>`kMaxSourceLidar`：驱动支持的最大雷达数（如 16）；<br><br>注释：“The index is the handle”（数组索引即雷达句柄） | 存储所有雷达设备的状态和数据：<br><br>- 每个元素包含雷达连接状态、点云队列、IMU 队列、设备信息；<br><br>- 公有设计：让 Lddc 直接访问雷达队列，减少接口封装的开销。                                   |
| `Semaphore pcd_semaphore_;`             | 信号量（自定义 Semaphore 类），点云数据同步用                                                                                        | 生产 - 消费同步核心：<br><br>- 生产者（Lds）推送点数据后 `Post()` 信号量；<br><br>- 消费者（Lddc）调用 `Wait()` 阻塞等待新数据；<br><br>公有设计：让 Lddc 直接调用 `Wait()`，简化同步逻辑。 |
| `Semaphore imu_semaphore_;`             | 信号量，IMU 数据同步用                                                                                                       | 与 `pcd_semaphore_` 逻辑一致，专用于 IMU 数据的生产 - 消费同步。                                                                                      |

## 六、保护成员变量（子类可访问，封装核心参数）

| 变量声明                    | 类型 / 含义                                | 设计意图                                                                                                     |
| ----------------------- | -------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `double publish_freq_;` | 浮点型，数据发布频率（Hz）                         | 子类（如 LdsLidar）生产数据时，根据该频率控制推送速率（如 10Hz 则每 100ms 推送一帧）；<br><br>保护设计：允许子类修改（如 LVX 文件数据源可适配文件帧率），但禁止外部直接修改。 |
| `uint8_t data_src_;`    | 无符号字符型，数据源类型（对应 `LidarDataSourceType`） | 子类根据该值适配数据处理逻辑（如 `data_src_ == kSourceLvxFile` 则解析文件，而非连接硬件）；<br><br>保护设计：子类可读取 / 修改，外部仅能通过接口设置。         |

## 七、私有成员变量（仅自身访问，核心状态）

| 变量声明                           | 类型 / 含义                                                                | 设计意图                                                                                                                                                        |
| ------------------------------ | ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `volatile bool request_exit_;` | 布尔型（volatile 修饰），退出请求标志；<br><br>`volatile`：保证多线程下变量的可见性（避免编译器优化导致读取旧值） | 核心退出控制变量：<br><br>- 仅 Lds 自身可修改（通过 `RequestExit()`/`CleanRequestExit()`）；<br><br>- 外部仅能通过 `IsRequestExit()` 读取；<br><br>私有 + volatile：保证线程安全，避免外部误修改导致退出逻辑异常。 |

## 八、类设计总结

1. **抽象与扩展**：虚析构 + 虚函数 `PrepareExit()` 为子类扩展预留接口，适配不同数据源的差异化逻辑；
2. **线程安全**：`volatile` 标志位 + 信号量，保证多线程（生产 / 消费）下的数据安全和退出安全；
3. **多雷达管理**：通过句柄映射 + 数组存储，简化多雷达组网的状态和数据管理；
4. **封装与开放**：公有变量供核心消费逻辑（Lddc）直接访问，保护变量供子类扩展，私有变量保证核心状态不被篡改；
5. **工程容错**：队列状态检查、退出预处理等函数，保证驱动在异常场景（硬件掉线、文件损坏）下的鲁棒性。

```cpp
class Lds {
 public:
  Lds(const double publish_freq, const uint8_t data_src);
  virtual ~Lds();

  void StorageImuData(ImuData* imu_data);
  void StoragePointData(PointFrame* frame);
  void StorageLvxPointData(PointFrame* frame);

  int8_t GetHandle(const uint8_t lidar_type, const PointPacket* lidar_point);
  void PushLidarData(PointPacket* lidar_data, const uint8_t index, const uint64_t base_time);

  static void ResetLidar(LidarDevice *lidar, uint8_t data_src);
  static void SetLidarDataSrc(LidarDevice *lidar, uint8_t data_src);
  void ResetLds(uint8_t data_src);

  void RequestExit();

  bool IsAllQueueEmpty();
  bool IsAllQueueReadStop();

  void CleanRequestExit() { request_exit_ = false; }
  bool IsRequestExit() { return request_exit_; }
  virtual void PrepareExit(void);

  // get publishing frequency
  double GetLdsFrequency() { return publish_freq_; }

 public:
  uint8_t lidar_count_;                 /**< Lidar access handle. */
  LidarDevice lidars_[kMaxSourceLidar]; /**< The index is the handle */
  Semaphore pcd_semaphore_;
  Semaphore imu_semaphore_;
  static CacheIndex cache_index_;
 protected:
  double publish_freq_;
  uint8_t data_src_;
 private:
  volatile bool request_exit_;
};
```
