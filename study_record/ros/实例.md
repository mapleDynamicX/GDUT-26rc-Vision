# 实例

在 ROS 1 的 C++ 中，**发布者（`ros::Publisher`）不需要绑定类实例，而订阅者（`ros::Subscriber`）需要绑定**，核心原因在于 **两者的核心操作与回调机制不同**—— 发布者是 “主动触发消息发送”，订阅者是 “被动接收消息并触发回调”，而回调函数的调用依赖类实例的上下文。

### 1. 先明确：“绑定实例” 的本质是什么？

在类中使用订阅者时，我们通常会将 **类的非静态成员函数作为回调函数**（因为需要访问类的成员变量 / 方法）。而 C++ 中，**非静态成员函数的调用必须依赖一个具体的类实例**（隐含 `this` 指针参数）—— 如果不绑定实例，ROS 无法知道 “哪个对象的成员函数” 需要被调用，会导致编译报错或运行时崩溃。

“绑定实例” 的核心就是：通过 `boost::bind`（ROS 1 常用）将 **类实例指针（`this`）** 与 **成员函数** 绑定，生成一个可独立调用的函数对象，供 ROS 回调触发。

### 2. 发布者：为什么不需要绑定实例？

`ros::Publisher` 的核心操作是 **主动调用 `publish()` 方法发送消息**，这个过程不涉及 “回调函数”，而是由你直接控制：

- 你在类的成员函数中（比如 `sendMessage()`），通过 `this->publisher_.publish(msg)` 触发发送 —— 这里的 `this` 已经明确指向当前类实例，`publish()` 是 `ros::Publisher` 对象的成员方法，调用时只需要消息参数，不需要额外依赖 “外部触发的回调”。
- `ros::Publisher` 本身只是一个 “消息发送器”，它的核心是与 ROS Master 注册话题、管理消息队列，**不持有任何回调函数**，自然不需要绑定类实例。

简单说：发布者是 “你调用它”，调用时已经有明确的实例上下文（`this`），无需提前绑定。

### 3. 订阅者：为什么必须绑定实例？

`ros::Subscriber` 的核心操作是 **被动接收消息，并触发你指定的回调函数**—— 这个回调函数的调用权在 ROS 框架手中（当有消息到达时，ROS 会自动调用）。这里的关键问题是：**ROS 不知道你的回调函数属于哪个类实例**。

具体来说：

- 如果你把 **类的非静态成员函数作为回调**（比如 `void MyClass::callback(const std_msgs::String::ConstPtr& msg)`），这个函数的完整签名其实是 `void callback(MyClass* this, const std_msgs::String::ConstPtr& msg)`——`this` 指针是隐含的第一个参数，指向类实例。
- ROS 框架在触发回调时，只能传递 “消息参数”（`std_msgs::String::ConstPtr`），无法自动获取 `this` 指针（它不知道你要调用哪个对象的 `callback` 方法）。
- 因此，你必须通过 `boost::bind(&MyClass::callback, this, _1)` 将 `this`（当前实例指针）与回调函数绑定，生成一个 “带实例上下文的函数对象”—— 这样 ROS 调用时，就知道要通过 `this` 指针访问你的类实例，进而执行回调。

如果不绑定实例：

- 编译会报错：`error: no matching function for call to ‘ros::Subscriber::subscribe(...)’`，因为 ROS 找不到 “无需实例即可调用的回调函数”（非静态成员函数必须依赖实例）。
- 即使强行编译（比如用静态成员函数），也无法访问类的非静态成员变量 / 方法，失去了类封装的意义。

### 4. 关键对比：发布者 vs 订阅者

| 特性    | 发布者（`ros::Publisher`）    | 订阅者（`ros::Subscriber`）       |
| ----- | ------------------------ | ---------------------------- |
| 核心操作  | 主动调用 `publish(msg)` 发送消息 | 被动接收消息，触发回调函数                |
| 依赖上下文 | 调用时由 `this` 明确实例（你主动控制）  | 回调时需由 ROS 触发，需提前绑定实例（`this`） |
| 函数类型  | 无回调，仅调用 `publish()` 方法   | 需指定回调函数（非静态成员函数需绑定实例）        |
| 绑定目的  | 无需绑定（无回调）                | 让 ROS 知道 “哪个实例的回调函数” 需要被调用   |

### 5. 补充：静态成员函数的特殊情况

如果你的订阅者回调函数是 **类的静态成员函数**，其实也不需要绑定实例 —— 但静态成员函数不能访问类的非静态成员（无 `this` 指针），只能处理全局 / 静态数据，实际使用中极少场景适用。
